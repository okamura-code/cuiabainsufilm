Guia de lançamento — site Cuiabá Insulfilm

Roteiro do dia: domínio no Registro.br, hospedagem grátis no Cloudflare Pages, Google Search Console e Perfil da Empresa no Google. Preparado em 08/11/2026 e atualizado em 09/11/2026, a partir das páginas oficiais citadas em cada etapa.

Site já no ar (09/11/2026): https://cuiaba-insulfilm.pages.dev — público, sem login, com a logo na miniatura do WhatsApp. É este o link para mostrar ao cliente.
Como está montado: Cloudflare Pages, conta okamuraextra@gmail.com, projeto cuiaba-insulfilm, ligado ao GitHub okamura-code/cuiabainsufilm, branch main (cada push publica sozinho). Build npm run build, saída dist, Node 22 fixado em .node-version.
Falta: domínio .com.br no Registro.br em nome do cliente (CPF ou CNPJ dele), apontar para a Cloudflare, Search Console e Perfil da Empresa.

Ordem recomendada (meia tarde é suficiente)

  1. Registrar o domínio no Registro.br e pagar (Pix ativa na hora). Cliente faz, você orienta.
  2. Na Cloudflare (conta já existe), adicionar o domínio (zona), anotar os 2 servidores DNS.
  3. No Registro.br, trocar os servidores DNS do domínio para os da Cloudflare.
  4. Criar o projeto Pages a partir do GitHub — feito: cuiaba-insulfilm.pages.dev.
  5. Trocar o endereço do site no código (3 arquivos), push em main.
  6. Adicionar o domínio e o www ao projeto Pages; testar.
  7. Search Console: propriedade de Domínio, TXT no DNS da Cloudflare, sitemap.
  8. Perfil da Empresa no Google: colocar o site, conferir telefone e horário.

1. Domínio no Registro.br

ItemDado oficial
PreçoR$ 40,00 por 1 ano (R$ 76 por 2 anos, R$ 112 por 3). Alterações de dados não custam nada.
Quem podePessoa física maior de idade (CPF) ou jurídica (CNPJ) estabelecida no Brasil. Data de nascimento é exigida para validar o CPF.
PagamentoPix, cartão de crédito Visa ou MasterCard, ou boleto. Instruções chegam no e-mail de confirmação do registro.
Nome2 a 26 caracteres antes do .com.br; letras, números, hífen e acentos; não pode começar nem terminar com hífen.
DNS no registroSão necessários 2 servidores DNS. Se não informar nenhum, o Registro.br usa os servidores dele e o domínio é registrado em até 5 minutos (sem outra pendência). Dá para trocar depois.

Passo a passo

  1. Em registro.br, pesquisar o nome desejado. Sugestões a testar, nesta ordem: cuiabainsulfilm.com.br, cuiabainsulfilm.com (se quiser os dois, o .com fica para depois), insulfilmcuiaba.com.br. Só registra se aparecer "Domínio disponível para registro".
  2. Clicar em Registrar. Criar a conta do cliente: nome completo da pessoa (não nome genérico), CPF ou CNPJ do titular, e-mail que ele acessa, endereço com CEP, data de nascimento. Dica: ativar o Token (verificação em duas etapas) em "Segurança" depois do registro.
  3. Na tela de servidores DNS, deixar os do Registro.br por enquanto (o domínio ativa em minutos). Trocar para a Cloudflare na etapa 3.
  4. Pagar com Pix (mais rápido). Guardar a fatura de Registro (não existe nota fiscal para esse serviço).
  5. Anotar: usuário do Registro.br, e-mail, e quem é o contato do titular. O cliente é o dono; você pode ser cadastrado só como contato técnico, que basta para mexer em DNS.
Atenção. Não é possível renomear um domínio depois de registrado; conferir a grafia antes de pagar. Cobrança de renovação chega por e-mail 30 dias antes de vencer; o Registro.br não manda boleto pelo correio.

Fontes: registro.br/ajuda/pagamento-de-dominio/ · registro.br/ajuda/registro-de-novos-dominios/ · registro.br/dominio/regras/ · registro.br/ajuda/gerenciamento-de-conta/dns/ (lidas em 08/11/2026).

2. Domínio como zona na Cloudflare

  1. Entrar em dash.cloudflare.com com a conta que já hospeda o site (okamuraextra@gmail.com). Se o cliente quiser conta própria: Sign up com o e-mail dele (plano Free) e refazer a etapa 4 lá; leva 5 minutos.
  2. Menu Domains → Onboard a domain → digitar o domínio raiz (ex.: cuiabainsulfilm.com.br) → escolher "quick scan" dos registros DNS → Continue → selecionar o plano Free → revisar os registros → Continue.
  3. A Cloudflare mostra dois servidores DNS (algo como ana.ns.cloudflare.com e bob.ns.cloudflare.com). Copiar os dois exatamente. Eles também ficam na página Overview da zona.
  4. Se o domínio tiver DNSSEC ativo no Registro.br, desativar antes de trocar os servidores.

Fontes: developers.cloudflare.com/fundamentals/manage-domains/add-site/ · developers.cloudflare.com/dns/zone-setups/full-setup/setup/

3. Trocar os servidores DNS no Registro.br

  1. Entrar em registro.br com a conta do cliente → clicar no nome do domínio.
  2. Na tela do domínio, campos de servidores DNS: apagar os do Registro.br e colar os dois da Cloudflare (sem IP; só é preciso IP quando o servidor DNS está dentro do próprio domínio, o que não é o caso). Salvar.
  3. Publicação do Registro.br acontece a cada 5 minutos; a Cloudflare diz para esperar até 24 h, na prática costuma levar de minutos a poucas horas. A zona na Cloudflare muda de "Pending Nameserver Update" para Active e chega um e-mail.
Quem pode fazer essa troca: contato do titular, administrativo ou técnico do domínio. Por isso vale cadastrar você como contato técnico.

Fontes: registro.br — item 5.5 "Como faço para alterar os servidores DNS" · Cloudflare — full setup

4. Projeto no Cloudflare Pages (hospedagem) — feito em 09/11

Já está publicado em https://cuiaba-insulfilm.pages.dev. Passos usados, para repetir na conta do cliente se ele preferir:

  1. Painel Cloudflare → Workers & Pages → Create application → Pages → Import an existing Git repository → Connect GitHub → instalar o app "Cloudflare Workers and Pages" na conta GitHub, só no repositório cuiabainsufilm → Install & Authorize.
  2. Selecionar o repositório → em "Set up builds and deployments": Project name cuiaba-insulfilm; Production branch main; Build command npm run build; Build output directory dist (ou preset Astro, que preenche os dois). Sem variáveis de ambiente.
  3. Save and Deploy. Build leva 1 a 2 minutos.
  4. Conferido no ar: vídeo da abertura, /robots.txt, /sitemap-index.xml, imagem de prévia /media/og.jpg (logo 1200×630).
Projeto criado pela integração Git não pode virar "Direct Upload" depois. A Cloudflare já oferece "Workers com static assets" como sucessor do Pages; o Pages continua aceitando projetos novos (doc atualizada em 04/2026). Se um dia migrar, o Workers exige DNS na Cloudflare, que é justamente o que estamos fazendo.

Fontes: pages/get-started/git-integration/ · pages/configuration/build-configuration/ · pages/configuration/build-image/ (Node padrão 22.23.4; .node-version fixa a versão).

6. Domínio próprio no projeto Pages

  1. Workers & Pages → projeto → aba Custom domains → Set up a domain → digitar cuiabainsulfilm.com.br → Continue. Como a zona já está na Cloudflare, ela cria o registro DNS sozinha. HTTPS automático.
  2. Repetir para www.cuiabainsulfilm.com.br.
  3. Opcional, redirecionar www → raiz: Bulk Redirects (lista com Source www.dominio → Target https://dominio, 301, marcando preservar query, subpath e path suffix) e, em DNS, registro A www → 192.0.2.1 com proxy ligado. Pode ficar para outro dia; sem isso, www e raiz servem o mesmo site, e o canonical já aponta para a raiz.
Não criar CNAME na mão antes de adicionar o domínio no painel do Pages (dá erro 522). Domínio raiz só funciona com a zona na Cloudflare, por isso a etapa 3 vem antes.

Fontes: pages/configuration/custom-domains/ · pages/how-to/www-redirect/

7. Google Search Console

  1. Entrar em search.google.com/search-console com a conta Google do cliente (a mesma do Perfil da Empresa, de preferência) → Adicionar propriedade → tipo Domínio → cuiabainsulfilm.com.br. O tipo Domínio cobre www, sem www, http e https de uma vez; só aceita verificação por DNS.
  2. O Google mostra um registro TXT no formato google-site-verification=.... Copiar.
  3. Na Cloudflare → zona do domínio → DNS → Add record: tipo TXT, nome @, conteúdo = a string copiada, TTL Auto → Save. Na Cloudflare costuma propagar em minutos (o Google avisa que pode levar até 2 ou 3 dias em outros provedores).
  4. Voltar ao Search Console → Verificar. Se falhar, esperar alguns minutos e tentar de novo. Não apagar o registro TXT depois: ele mantém a verificação.
  5. Menu Sitemaps → colar https://cuiabainsulfilm.com.br/sitemap-index.xml → Enviar. O Google aceita índice de sitemaps e segue os arquivos listados.
  6. Menu Inspeção de URL → colar a home → Solicitar indexação. Há cota diária; pedir uma vez basta. Indexação leva de dias a semanas.

Fontes: Adicionar propriedade · Verificar propriedade (registro DNS) · Sitemaps · Pedir rastreamento

8. Perfil da Empresa no Google (Google Meu Negócio)

O perfil da loja já existe no Google Maps (31 avaliações, nota 5,0, endereço Carmindo de Campos, 75, Dom Aquino). Falta colocar o site e conferir os dados.

  1. Logado na conta Google que administra o perfil, pesquisar no Google o nome da empresa ou "minha empresa" → aparece o painel do perfil → Editar perfil. Pelo app Google Maps: aba Empresa → Editar perfil.
  2. Em Informações comerciais → campo Site: colar o endereço completo com https:// (ex.: https://cuiabainsulfilm.com.br) → Salvar. Revisão do Google costuma levar até 10 minutos, em raros casos até 30 dias.
  3. Conferir no mesmo lugar: telefone (65) 99340-1663 igual ao do site, horário de funcionamento, categoria principal específica (ex.: "Loja de películas automotivas" ou equivalente disponível), descrição até 750 caracteres sem links, fotos da fachada e dos serviços.
  4. Se o perfil ainda não for do cliente: business.google.com/add → digitar nome e endereço → escolher a empresa → Solicitar acesso. O dono atual tem 3 dias para responder; sem resposta, dá para reivindicar pelo e-mail de confirmação. Métodos de verificação possíveis: vídeo ao vivo, telefone/SMS, e-mail, cartão-postal (até 14 dias) ou, instantâneo, pelo Search Console já verificado.

Fontes: Editar informações do perfil · Status das edições · Verificar a empresa · Solicitar acesso a um perfil

9. Checklist final e depois do lançamento

  • Domínio registrado e pago; servidores DNS = Cloudflare; zona Active.
  • Pages publicado em cuiaba-insulfilm.pages.dev (feito); domínio e www adicionados; HTTPS ativo.
  • Código com o domínio final nos 3 arquivos; robots e sitemap abrindo no domínio.
  • Search Console verificado, sitemap enviado, indexação da home pedida.
  • Perfil da Empresa com o site, telefone e horário conferidos.
  • Teste no celular do cliente (Safari): abertura, rolagem, simulador, WhatsApp.
  • Vercel antiga (cuiaba-insulfilm.vercel.app, site velho): apagar o projeto depois do lançamento para não duplicar no Google. O endereço pages.dev continua existindo; o canonical aponta para o domínio, então não concorre.
  • Guardar em lugar seguro do cliente: login Registro.br, login Cloudflare, conta Google usada. Renovação do domínio vence em 1 ano.
Pendências antigas que continuam com o dono: uso comercial das capturas de vídeo da garagem, áudio dos vídeos, confirmar o pino do mapa, linha Window Blue aplicada, tonalidades Premium.
